# AI 应用开发小团队：本轮产品交付记录

日期：2026-10-31。目标人群为用户明确选择的「AI 应用开发小团队：知识库、工作流和应用部署」。本轮以应用从原型、资源、编排、测试、发布、观测到迭代的路径组织产品，没有删除原有训练、模型网站或图谱工具。

本文记录源码中已落地的差异、已执行的验证，以及尚需环境或外部服务的条件。它不表示所有历史功能均已完成实地验证，不表示已生产部署，也不以「100% 完成」代替证据。后端与浏览器的精确记录见验证小节及独立报告。

## 核心变化

此前用户主要管理工作流、知识库、Agent 等资源，没有统一的可测试、可发布、可调用的交付对象。本轮新增一等「应用」对象，支持两种类型：

- **知识助手**：绑定有权限的知识集合、系统提示词和检索参数，执行真实检索与回答链路。
- **自动化应用**：绑定真实工作流，复用现有节点和执行引擎。

两类应用共享草稿、测试请求、发布版本、应用密钥与请求记录。没有把专用 CV 网站生成器改名充当通用应用发布，也没有把模板市场或 Agent 市场的发布等同于运行时上线。

| 实施前的断点 | 本轮实现后的行为 |
| --- | --- |
| 首页堆叠工具入口，缺少交付对象 | 交付工作台显示真实应用和近期请求；主导航优先应用中心、知识库、工作流、执行记录与运行监控。 |
| 原资源修改与线上行为缺少隔离 | 草稿和线上版本分开管理；工作流发布使用隐藏的不可变图快照，后续修改源图不改写已发布定义。 |
| 测试成功与发布没有固定证明 | 测试记录绑定草稿及实际资源指纹；新发布必须通过服务端再次校验，并固定成功测试请求与完成时间。 |
| 无应用专属调用入口 | 当前 Flowly 服务提供发布版本 invoke API、只授权单个应用的密钥、撤销与有效期。 |
| 出错后难定位具体交付版本 | 请求记录保留实际模式、版本、状态、输入输出、错误、耗时及可归因用量，支持详情深链接。 |
| 未知用量、加载失败容易被表达为 0 | 应用与 Agent 调试器明确显示未提供；统计和账单提供真实失败、重试及缺失状态。 |

## 测试、发布与调用的真实边界

1. **先保存、再测试、再发布**。真实执行失败、无知识证据、无可用模型或节点错误均不能成为可发布的成功证明。源资源变化后，服务端检查测试是否仍对应当前指纹。
2. **工作流定义固定，知识内容实时**。工作流 release 固定实际图与递归子图；知识助手固定集合绑定、提示词和检索配置，但仍读取集合的实时文档内容。知识文档变化可能影响线上回答，不能称为整库快照。
3. **发布作用于当前服务**。发布是在当前 Flowly 服务激活一个版本与 API，不自动创建云主机、不购买域名、不承诺公网已可访问。外部调用地址取决于实际部署与网络。
4. **密钥只用于本应用调用**。创建时明文只展示一次，之后仅可见前缀与状态。撤销、到期或创建者失去相应权限后拒绝调用；不能用应用密钥读取管理页和其他请求。
5. **网络重试不等于新运行**。单次测试保留 Idempotency-Key；相同键和输入恢复原记录，运行中返回真实 running 状态。新运行使用新键，同键不同输入被拒绝。
6. **在途工作不伪取消**。接口采用总执行预算、真实请求记录和超时结算；第三方已发生的副作用不能承诺撤回。界面不提供仅改变本地状态的“取消成功”。
7. **未知费用保持未知**。没有供应商或链路提供的可归因 Token、费用和币种时返回空值，显示「未提供」，不按字符串估算，也不补假 0。
8. **团队资源边界不跨越**。资源绑定与应用归属一致；viewer 只读，编辑与发布权限分开。普通可见成员不能借发布、重建或隐藏图接口间接读取私有配置。

## 关联能力补齐与保留

- **工作流可靠性**：实时事件、握手失败和轮询降级；按工作流隔离文档加载、请求代次与编辑状态；未保存离开保护；历史快照容量与连续操作合并；不减少既有节点分支。
- **JSON 完整性**：公共 API 提供显式 opaque 子树边界，工作流模块覆盖创建、读取、保存、节点增改/批量、模板、导入导出、执行输入输出。元数据继续遵循接口命名约定，用户键与字面量不被递归改写；其他 API 默认行为保持。
- **子工作流**：接入真实执行、映射、同步/异步、错误策略、权限重验和共享预算；异步返回实际 child execution，测试等待真实结果。版本选择只展示 latest 与实际当前版本，不生成假历史版本。
- **流式调试**：Agent 流式响应按 UTF-8 完整帧处理，维护响应式消息、结束/错误/断开状态、过期响应和 abort 清理。旧工作流 stream 封装统一使用真实 Bearer 的 POST 与 AbortSignal，不在 URL 携带 token。
- **模型网站来源**：站点 owner、团队和源流程/节点/执行由可信执行上下文与数据库状态核验。重建接口只接站点 ID，由后台授权解析可重建配置；事务中创建完整图，重复提交可恢复同一操作，不复制数据库凭据或伪造源 ID。
- **个人数据管理**：自动备份策略保存在后台；恢复先展示范围，再创建副本；个人数据删除先预览、校验密码与确认文本。界面明确不包含团队、知识库文件和独立凭证库等超出当前范围的数据。
- **账单凭证**：下载实际服务端可打印账单凭证，可由用户打印或保存 PDF；不是伪造下载成功，不等于第三方支付完成或法定税务发票。
- **高级工具保留**：数据集、训练权重、模型应用网站、向量存储、代码图谱、多智能体协作、API 测试与流程对比仍有原入口。它们被收纳而非删除。

本轮也完成关联基础治理：模板及市场写操作按 owner/admin 校验；桌面设备注册、派单和 WebSocket 均复核身份及归属；训练任务支持真实取消、重试和过期回调隔离，标准训练入口使用实际绝对路径。媒体节点从大服务类分离并保留原分支；工作流列表采用有界摘要和聚合查询，详情继续返回完整图。桌面主窗口、IPC、导航和子进程按可信来源控制，测试 profile 不使用用户凭据或连接真实云端。部署增加同源入口、静态/API 代理边界、健康检查、固定镜像与回滚工具；本地验证不等于已经远程发布。

## 界面与信息结构

主导航分为「应用交付」「构建能力」「高级工具」「团队与资源」。主操作是创建应用；高级工具和资源仍可访问。应用列表使用可比较的行、真实状态和稳定列，详情使用配置、测试、发布、请求的工作区边界。

新界面复用四主题语义变量与统一 delivery tokens：深石墨/冷灰表面、青绿交互点、细分隔线、可见焦点和具体状态文案。Landing 不采用虚构经营数据和写死报价。加载、失败、空态、权限不足与未知用量被作为内容表达。

新交付界面在 prefers-reduced-motion 下显式关闭过渡与动画；范围限定 Landing、交付工作台和应用中心，其他既有业务页面保留原有策略。此处是浏览器检查后的小范围样式修正，不涉及业务规则。
