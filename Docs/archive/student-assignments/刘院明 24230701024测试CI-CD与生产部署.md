# 第 1 章　引言

## 1.1　项目设计需求

### 1.1.1　研究背景

随着大语言模型（LLM）技术的快速发展与广泛应用，AI Agent（人工智能代理）正逐步成为人工智能应用的主流形态。AI Agent 能够自主感知环境、做出决策并执行动作，在智能问答、自动化办公、数据分析、内容生成等众多场景中展现出巨大潜力。然而，构建一个完整的 AI Agent 应用往往需要整合多个组件——包括 LLM 调用、工作流编排、外部工具调用、记忆管理、RAG（检索增强生成）等——这对开发者的技术能力提出了较高要求，也使得 AI 应用的开发效率受到制约。

当前市场上虽然已有一些工作流编排工具（如 LangFlow、ComfyUI、Dify 等），但在以下方面仍存在明显不足：

- **缺乏深度 LLM 集成**：多数工具仅支持简单的 API 调用，缺乏对 Agent 推理链、多模型协作、工具调用等高级能力的产品化支持；
- **可视化与灵活性的平衡欠佳**：部分工具要么过于简陋、缺乏可视化编辑器，要么过度封装导致灵活性不足；
- **实时性与可观测性薄弱**：工作流执行过程中的状态监控、日志追踪、异常告警等可观测性能力普遍缺失；
- **多租户与团队协作能力不足**：难以满足企业级团队协作与多项目管理的需求。

### 1.1.2　设计目标

本项目旨在设计并实现一个名为 **Flowly** 的 AI Agent 工作流编排平台，核心设计目标如下：

1. **可视化工作流编辑器**：提供基于拖拽的可视化编辑器，使非技术用户也能构建复杂工作流；
2. **多模型 LLM 网关**：统一接入 OpenAI GPT、Anthropic Claude 系列模型；
3. **AI Agent 生命周期管理**：支持 Agent 的创建、配置、调试和部署；
4. **自然语言生成工作流**：用户以自然语言描述需求，系统自动生成工作流草图；
5. **实时执行监控**：通过 WebSocket 实现执行过程的实时推送；
6. **RAG 知识增强**：提供完整的检索增强生成管线；
7. **多租户与团队协作**：支持团队成员权限管理与工作流共享。

### 1.1.3　设计约束与可行性分析

- **技术栈选型**：前端 Vue 3 + Vite + Element Plus + Vue Flow，后端 Django 5 + DRF，均为业界主流框架；
- **开发时间**：课程时间为 2026.4.20—2026.4.30（约 10 天），优先实现核心功能；
- **成本约束**：优先使用开源技术栈，开发测试成本可控。

        assert sample_workflow.version == original_version + 1

        assert execution.status == 'running'

# monitoring/views.py
class HealthCheckView(APIView):
    """系统健康检查"""
    permission_classes = []

    def get(self, request):
        checks = {
            'database': self._check_database(),
            'redis': self._check_redis(),
            'celery': self._check_celery(),
        }

        all_healthy = all(c['status'] == 'healthy' for c in checks.values())
        status_code = status.HTTP_200_OK if all_healthy else status.HTTP_503_SERVICE_UNAVAILABLE

        return Response({
            'status': 'healthy' if all_healthy else 'unhealthy',
            'checks': checks,
            'timestamp': timezone.now().isoformat(),
        }, status=status_code)

    def _check_database(self):
        try:
            from django.db import connection
            with connection.cursor() as cursor:
                cursor.execute("SELECT 1")
            return {'status': 'healthy'}
        except Exception as e:
            return {'status': 'unhealthy', 'error': str(e)}

    def _check_redis(self):
        try:
            from django.core.cache import cache
            cache.set('health_check', 'ok', 10)
            return {'status': 'healthy'}
        except Exception as e:
            return {'status': 'unhealthy', 'error': str(e)}

    def _check_celery(self):
        try:
            from config.celery import app
            inspect = app.control.inspect()
            active = inspect.active()
            return {'status': 'healthy', 'workers': list(active.keys()) if active else []}
        except Exception as e:
            return {'status': 'unhealthy', 'error': str(e)}

3. **监控体系基础薄弱**：当前仅实现了基础的服务健康检查，尚未接入 Prometheus + Grafana 进行细粒度指标监控。

## 4.2　技术收获

1. **pytest 深度实践**：掌握了 pytest 的 fixtures、markers、parametrize、mock 等高级特性，理解了单元测试和集成测试的边界划分；
2. **Playwright E2E 测试**：掌握了 Playwright 的页面对象模型（POM）、异步定位器、API 测试拦截等实践技巧；
3. **GitHub Actions 自动化**：深入实践了 CI/CD 流水线的设计，理解了流水线 stages、jobs、dependencies 的配置关系；
4. **Docker 容器化**：掌握了多容器应用的 Docker Compose 编排、服务健康检查、卷挂载、环境变量管理等生产级技能；
5. **Nginx 反向代理**：理解了 Nginx 的 upstream 负载均衡、SSL 终止、静态文件服务等配置方法。

## 4.3　改进方向

1. **提升测试覆盖率**：为 RAG、billing 等模块补充测试用例，目标是后端整体覆盖率 ≥ 80%，核心模块 ≥ 90%；
2. **完善 E2E 测试**：扩展 Playwright E2E 测试覆盖范围，增加 Agent 调试、NL 生成等页面的端到端测试；
3. **Prometheus + Grafana**：接入 Prometheus 采集应用指标和基础设施指标，Grafana 构建企业级监控大盘；
4. **蓝绿部署**：引入蓝绿部署策略，实现生产环境的零停机部署和快速回滚；
5. **安全扫描**：在 CI 流水线中加入 SAST（静态应用安全测试）工具（如 Bandit、Semgrep），提升代码安全性。

## 4.4　课程心得

本次课程设计让我深刻认识到了"质量"和"效率"之间的辩证关系。测试和 CI/CD 看似是"拖慢开发速度"的工作，但实际上它们是保障长期开发效率的关键设施。一个没有自动化测试的项目，每次修改代码都需要大量的人工回归测试；一个没有 CI/CD 的项目，每次部署都需要手动操作，容易出错且难以追溯。

特别是在编写测试的过程中，我学会了从"使用者"的角度审视代码设计。当一段代码难以测试时，往往说明它的设计存在问题——依赖关系不清晰、职责不单一、副作用难以控制。通过为 `WorkflowExecutor` 编写单元测试，我重新审视了其设计，发现了一些之前没有意识到的边界情况（如空工作流、单节点工作流等），这些发现反过来又促进了代码的改进。

此外，Docker 容器化部署也让我理解到了"环境一致性"的重要性。"在我机器上能跑"不再是一个问题——通过 Docker，无论是开发机、测试服务器还是生产环境，都运行在相同的容器镜像上，环境差异被彻底消除。这种一致性对于团队协作和问题排查都带来了极大的便利。

这次课程设计让我从一个更宏观的视角理解了软件工程——代码开发只是整个软件生命周期的一部分，测试、部署、监控、运维同样重要。只有将这些环节都纳入考量，才能构建出真正可靠、可维护的软件系统。
