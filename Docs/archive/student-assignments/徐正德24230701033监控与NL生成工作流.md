# 第 1 章　引言

## 1.1　项目设计需求

### 1.1.1　研究背景

随着大语言模型（LLM）技术的快速发展与广泛应用，AI Agent（人工智能代理）正逐步成为人工智能应用的主流形态。AI Agent 能够自主感知环境、做出决策并执行动作，在智能问答、自动化办公、数据分析、内容生成等众多场景中展现出巨大潜力。然而，构建一个完整的 AI Agent 应用往往需要整合多个组件——包括 LLM 调用、工作流编排、外部工具调用、记忆管理、RAG（检索增强生成）等——这对开发者的技术能力提出了较高要求，也使得 AI 应用的开发效率受到制约。

当前市场上虽然已有一些工作流编排工具（如 LangFlow、ComfyUI、Dify 等），但在以下方面仍存在明显不足：

- **缺乏深度 LLM 集成**：多数工具仅支持简单的 API 调用，缺乏对 Agent 推理链、多模型协作、工具调用等高级能力的产品化支持；
- **可视化与灵活性的平衡欠佳**：部分工具要么过于简陋、缺乏可视化编辑器，要么过度封装导致灵活性不足；
- **实时性与可观测性薄弱**：工作流执行过程中的状态监控、日志追踪、异常告警等可观测性能力普遍缺失；
- **多租户与团队协作能力不足**：难以满足企业级团队协作与多项目管理的需求。

### 1.1.2　设计目标

本项目旨在设计并实现一个名为 **Flowly** 的 AI Agent 工作流编排平台，核心设计目标如下：

1. **可视化工作流编辑器**：提供基于拖拽的可视化编辑器，使非技术用户也能构建复杂工作流；
2. **多模型 LLM 网关**：统一接入 OpenAI GPT、Anthropic Claude 系列模型；
3. **AI Agent 生命周期管理**：支持 Agent 的创建、配置、调试和部署；
4. **自然语言生成工作流**：用户以自然语言描述需求，系统自动生成工作流草图；
5. **实时执行监控**：通过 WebSocket 实现执行过程的实时推送；
6. **RAG 知识增强**：提供完整的检索增强生成管线；
7. **多租户与团队协作**：支持团队成员权限管理与工作流共享。

### 1.1.3　设计约束与可行性分析

- **技术栈选型**：前端 Vue 3 + Vite + Element Plus + Vue Flow，后端 Django 5 + DRF，均为业界主流框架；
- **开发时间**：课程时间为 2026.4.20—2026.4.30（约 10 天），优先实现核心功能；
- **成本约束**：优先使用开源技术栈，开发测试成本可控。

Flowly 平台采用**分层架构**设计：

```
┌─────────────────────────────────────────────┐
│           Presentation Layer (前端)            │
│  Vue 3 + Vite + Element Plus + Vue Flow      │
├─────────────────────────────────────────────┤

├─────────────────────────────────────────────┤
│              Data Layer                       │

│           Infrastructure Layer                 │

**前后端通信机制：**

- **HTTP REST API**：所有 CRUD 操作通过 RESTful API 完成；
- **WebSocket**：工作流执行日志、Agent 对话流式输出通过 WebSocket 实时推送；
- **Celery + Redis**：耗时任务通过 Celery 异步处理，结果通过 WebSocket 回调推送。

### 2.4.2　数据模型设计

核心数据模型：

- **Tenant（租户）**：多租户隔离
- **User（用户）**：JWT 认证

class ExecutionLog(BaseModel):
    """工作流执行日志"""
    execution = models.ForeignKey('workflows.WorkflowExecution',
                                  related_name='logs', on_delete=models.CASCADE)
    node_id = models.CharField(max_length=100)
    node_name = models.CharField(max_length=255)
    level = models.CharField(max_length=20, choices=[
        ('DEBUG', '调试'), ('INFO', '信息'),
        ('WARNING', '警告'), ('ERROR', '错误'),
    ])
    message = models.TextField()
    data = models.JSONField(null=True, blank=True)  # 扩展数据
    timestamp = models.DateTimeField(auto_now_add=True)

class AlertRule(BaseModel):
    """告警规则"""
    tenant = models.ForeignKey('tenants.Tenant', on_delete=models.CASCADE)
    name = models.CharField(max_length=255)
    condition_type = models.CharField(max_length=50, choices=[
        ('execution_failed', '执行失败'),
        ('execution_timeout', '执行超时'),
        ('node_error', '节点错误'),
        ('api_quota_exceeded', 'API 配额超限'),
    ])
    condition_config = models.JSONField()  # {threshold: 3, window: 3600}
    is_active = models.BooleanField(default=True)
    notify_channels = models.JSONField(default=list)  # [email, webhook]

class AuditLog(BaseModel):
    """审计日志"""
    tenant = models.ForeignKey('tenants.Tenant', on_delete=models.CASCADE)
    user = models.ForeignKey('users.User', on_delete=models.SET_NULL, null=True)
    action = models.CharField(max_length=100)  # create_workflow, delete_agent, etc.
    resource_type = models.CharField(max_length=50)
    resource_id = models.CharField(max_length=100)
    details = models.JSONField(null=True, blank=True)
    ip_address = models.GenericIPAddressField(null=True)
    timestamp = models.DateTimeField(auto_now_add=True)
```

### 2.4.3　关键算法设计

**自然语言生成工作流算法（ReAct 模式）：**

```python
NL_TO_WORKFLOW_PROMPT = """
你是一个专业的工作流设计助手。根据用户的需求描述，设计一个完整的工作流 JSON 结构。

## 可用节点类型及说明：
- start: 开始节点（必须有 1 个，无输入，1 个输出）
- end: 结束节点（必须有至少 1 个，无输出，多个输入）
- input: 输入节点（用户输入参数定义）
- llm: LLM 调用节点（调用大语言模型）
- http: HTTP 请求节点（调用外部 API）
- condition: 条件分支节点（if-else 分支）
- switch: 路由节点（多分支路由）
- loop: 循环节点（迭代执行）
- code: 代码节点（Python 代码执行）
- delay: 延时节点（等待指定秒数）
- variable: 变量节点（变量赋值）
- prompt: 提示词节点（提示词模板）
- tool: 工具节点（Agent 工具调用）
- output: 输出节点（输出结果定义）

## 输出格式（仅输出 JSON，不要任何其他内容）：
{
  "name": "工作流名称",
  "description": "工作流描述",
  "nodes": [
    {"id": "node_1", "type": "start", "position": {"x": 0, "y": 0}, "config": {}},
    {"id": "node_2", "type": "llm", "position": {"x": 200, "y": 0}, "config": {"model": "gpt-4", "prompt": "..."}},
    {"id": "node_3", "type": "end", "position": {"x": 400, "y": 0}, "config": {}}
  ],
  "edges": [
    {"id": "edge_1", "source": "node_1", "target": "node_2"},
    {"id": "edge_2", "source": "node_2", "target": "node_3"}
  ]
}

## 重要约束：
1. 必须有且仅有 1 个 start 节点
2. 必须有至少 1 个 end 节点
3. 所有节点 id 必须唯一
4. 每条边的 source 和 target 必须对应实际存在的节点 id
5. 节点位置要合理分布，避免连线交叉
6. 节点配置（config）要根据类型包含必要的参数
"""
```

├── views.py             # API 视图

class MonitoringService:
    """监控服务"""

    @staticmethod
    def record_execution_metrics(execution: WorkflowExecution):
        """记录执行指标"""
        duration = 0
        if execution.started_at and execution.completed_at:
            duration = (execution.completed_at - execution.started_at).total_seconds()

        ExecutionMetric.objects.create(
            tenant=execution.workflow.tenant,
            workflow=execution.workflow,
            execution=execution,
            status=execution.status,
            duration=duration,
            node_count=execution.workflow.definition['nodes'].__len__() if execution.workflow.definition else 0,
        )

    @staticmethod
    def get_execution_trend(tenant_id: int, days: int = 7) -> dict:
        """获取执行趋势数据（最近 N 天）"""
        from django.db.models import Count, Q
        from datetime import timedelta

        start_date = timezone.now() - timedelta(days=days)
        executions = WorkflowExecution.objects.filter(
            workflow__tenant_id=tenant_id,
            started_at__gte=start_date
        ).extra(
            select={'date': 'date(started_at)'}
        ).values('date').annotate(
            total=Count('id'),
            success=Count('id', filter=Q(status='success')),
            failed=Count('id', filter=Q(status='failed')),
        ).order_by('date')

        return list(executions)

    @staticmethod
    def get_node_duration_stats(tenant_id: int) -> dict:
        """获取各节点类型平均执行时长"""
        from django.db.models import Avg
        from django.db.models.functions import JSONObject

        # 关联 node_executions 获取节点级别的统计数据
        stats = NodeExecution.objects.filter(
            execution__workflow__tenant_id=tenant_id,
            completed_at__isnull=False
        ).values('node_type').annotate(
            avg_duration=Avg(F('completed_at') - F('started_at')),
            total_count=Count('id'),
            error_count=Count('id', filter=Q(status='failed'))
        )
        return list(stats)

    @staticmethod

        """检查告警规则并触发告警"""

# monitoring/alerting.py
class AlertChecker:
    @staticmethod
    def should_trigger(rule: AlertRule) -> bool:
        config = rule.condition_config
        window_seconds = config.get('window', 3600)
        threshold = config.get('threshold', 3)

        window_start = timezone.now() - timedelta(seconds=window_seconds)

        if rule.condition_type == 'execution_failed':
            count = WorkflowExecution.objects.filter(
                workflow__tenant=rule.tenant,
                status='failed',
                started_at__gte=window_start
            ).count()
            return count >= threshold

        elif rule.condition_type == 'execution_timeout':
            count = WorkflowExecution.objects.filter(
                workflow__tenant=rule.tenant,
                status='failed',
                error_message__contains='timeout',
                started_at__gte=window_start
            ).count()
            return count >= threshold

        return False

class AlertNotifier:
    @staticmethod
    def send(rule: AlertRule):
        for channel in rule.notify_channels:
            if channel == 'email':
                AlertNotifier._send_email(rule)
            elif channel == 'webhook':
                AlertNotifier._send_webhook(rule)
            elif channel == 'slack':
                AlertNotifier._send_slack(rule)

        # 记录告警历史
        AlertHistory.objects.create(
            rule=rule,
            triggered_at=timezone.now()
        )

```python
# nl_to_workflow/services.py
class NLToWorkflowService:
    """自然语言生成工作流服务"""

    def __init__(self, tenant_id: int, user_id: int):
        self.tenant_id = tenant_id
        self.user_id = user_id
        self.llm_gateway = LLMGateway(tenant_id=tenant_id)
        self.session = None

    def create_session(self) -> NLWorkflowSession:
        """创建新的 NL 生成会话"""
        self.session = NLWorkflowSession.objects.create(
            tenant_id=self.tenant_id,
            user_id=self.user_id,
            status='in_progress',
        )
        return self.session

    def generate(self, session_id: str, user_input: str) -> dict:
        """生成工作流"""
        self.session = NLWorkflowSession.objects.get(id=session_id)

        # 追加用户消息
        messages = self.session.messages or []
        messages.append({
            'role': 'user',
            'content': user_input,
            'timestamp': timezone.now().isoformat()
        })

        # 构建系统提示词
        system_prompt = self._build_system_prompt()

        # 调用 LLM
        response = self.llm_gateway.chat(
            model='gpt-4',
            messages=[
                {'role': 'system', 'content': system_prompt},
                *messages
            ],
            temperature=0.3,  # 低温度确保输出稳定
            max_tokens=4096,
        )

        # 解析 JSON 响应
        try:
            workflow_json = json.loads(response.content)
            # 验证工作流结构
            self._validate_workflow(workflow_json)

            # 更新会话
            messages.append({
                'role': 'assistant',
                'content': response.content,
                'timestamp': timezone.now().isoformat(),
                'workflow': workflow_json,
            })
            self.session.messages = messages
            self.session.generated_workflow = workflow_json
            self.session.status = 'completed'
            self.session.save()

            return workflow_json

        except (json.JSONDecodeError, WorkflowValidationError) as e:
            self.session.status = 'failed'
            self.session.save()
            raise NLGenerationError(f"工作流生成失败: {e}")

    def stream_generate(self, session_id: str, user_input: str) -> Iterator[dict]:
        """流式生成工作流"""
        self.session = NLWorkflowSession.objects.get(id=session_id)

        messages = self.session.messages or []
        messages.append({
            'role': 'user', 'content': user_input,
            'timestamp': timezone.now().isoformat()
        })

        system_prompt = self._build_system_prompt()

        buffer = ""
        async for chunk in self.llm_gateway.stream_chat(
            model='gpt-4',
            messages=[
                {'role': 'system', 'content': system_prompt},
                *messages
            ],
            temperature=0.3,
        ):
            buffer += chunk.delta
            yield {'type': 'chunk', 'content': chunk.delta, 'buffer': buffer}

        # 解析完整 JSON
        try:
            workflow_json = json.loads(buffer)
            self._validate_workflow(workflow_json)

            messages.append({
                'role': 'assistant', 'content': buffer,
                'timestamp': timezone.now().isoformat(),
                'workflow': workflow_json,
            })
            self.session.messages = messages
            self.session.generated_workflow = workflow_json
            self.session.status = 'completed'
            self.session.save()

            yield {'type': 'complete', 'workflow': workflow_json}

        except (json.JSONDecodeError, WorkflowValidationError) as e:
            self.session.status = 'failed'
            self.session.save()
            yield {'type': 'error', 'message': str(e)}

    def confirm_and_save(self, session_id: str, workflow_name: str) -> Workflow:
        """确认并保存为正式工作流"""
        session = NLWorkflowSession.objects.get(id=session_id)
        if not session.generated_workflow:
            raise ValueError("会话中无生成的工作流")

        workflow = Workflow.objects.create(
            tenant_id=self.tenant_id,
            name=workflow_name,
            description=session.generated_workflow.get('description', ''),
            definition={
                'nodes': session.generated_workflow['nodes'],
                'edges': session.generated_workflow['edges'],
            },
            status='draft',
            created_by_id=self.user_id,
        )

        session.status = 'confirmed'
        session.save()

        return workflow

    def _build_system_prompt(self) -> str:
        """构建系统提示词"""
        return NL_TO_WORKFLOW_PROMPT.strip()

    def _validate_workflow(self, workflow_json: dict):
        """验证工作流 JSON 结构"""
        if 'nodes' not in workflow_json or 'edges' not in workflow_json:
            raise WorkflowValidationError("缺少 nodes 或 edges 字段")

        node_ids = set()
        start_count = 0
        end_count = 0

        for node in workflow_json['nodes']:
            if 'id' not in node or 'type' not in node:
                raise WorkflowValidationError(f"节点缺少必要字段: {node}")
            node_ids.add(node['id'])
            if node['type'] == 'start':
                start_count += 1
            if node['type'] == 'end':
                end_count += 1

        if start_count != 1:
            raise WorkflowValidationError(f"必须有且仅有 1 个 start 节点，当前: {start_count}")
        if end_count < 1:
            raise WorkflowValidationError(f"必须至少有 1 个 end 节点，当前: {end_count}")

        for edge in workflow_json['edges']:
            if edge['source'] not in node_ids:
                raise WorkflowValidationError(f"边的 source 节点不存在: {edge['source']}")
            if edge['target'] not in node_ids:
                raise WorkflowValidationError(f"边的 target 节点不存在: {edge['target']}")
```

## 4.4　课程心得

本次课程设计让我深入体验了全栈开发的完整流程，特别是在实现执行监控模块时，我深刻体会到了"可观测性"在复杂系统中的重要性。一个没有监控的系统就像一个黑箱——出了问题无法定位，运行时无法优化。通过 WebSocket 实现实时日志推送、通过 ECharts 将枯燥的数据转化为直观的图表，这些工作让我理解了用户体验设计不仅适用于前端 UI，也同样适用于数据可视化。

在实现自然语言生成工作流的过程中，我学习到了提示词工程（Prompt Engineering）的精妙之处。通过精心设计的提示词模板，可以让 GPT-4 稳定地输出符合预期格式的 JSON 工作流定义。关键技巧包括：明确节点类型及说明、给出 JSON 输出示例、强调关键约束（如必须有 start 和 end 节点）、使用低温度参数确保输出的确定性。这些经验对于今后任何基于 LLM 的应用开发都有重要价值。

此外，这次课程设计也让我认识到了团队协作的重要性。监控模块和 NL 生成模块都涉及到前后端的深度配合——后端提供 WebSocket 推送和流式 API，前端负责实时渲染和用户交互。接口契约的提前约定、数据的序列化和反序列化、错误处理的一致性，每一个环节都需要团队成员之间的充分沟通。
