# 第 1 章　引言

## 1.1　项目设计需求

### 1.1.1　研究背景

随着大语言模型（LLM）技术的快速发展与广泛应用，AI Agent（人工智能代理）正逐步成为人工智能应用的主流形态。然而，构建一个完整的 AI Agent 应用往往需要整合多个组件——包括 LLM 调用、工作流编排、外部工具调用、记忆管理、RAG（检索增强生成）等——这对开发者的技术能力提出了较高要求，也使得 AI 应用的开发效率受到制约。

当前市场上虽然已有一些工作流编排工具（如 LangFlow、ComfyUI、Dify 等），但在以下方面仍存在明显不足：

- **缺乏深度 LLM 集成**：多数工具仅支持简单的 API 调用，缺乏对 Agent 推理链、多模型协作、工具调用等高级能力的产品化支持；
- **可视化与灵活性的平衡欠佳**：部分工具要么过于简陋、缺乏可视化编辑器，要么过度封装导致灵活性不足；
- **实时性与可观测性薄弱**：工作流执行过程中的状态监控、日志追踪、异常告警等可观测性能力普遍缺失；
- **多租户与团队协作能力不足**：难以满足企业级团队协作与多项目管理的需求。

### 1.1.2　设计目标

本项目旨在设计并实现一个名为 **Flowly** 的 AI Agent 工作流编排平台，核心设计目标如下：

1. **可视化工作流编辑器**：提供基于拖拽的可视化编辑器，使非技术用户也能构建复杂工作流；
2. **多模型 LLM 网关**：统一接入 OpenAI GPT、Anthropic Claude 系列模型；
3. **AI Agent 生命周期管理**：支持 Agent 的创建、配置、调试和部署；
4. **自然语言生成工作流**：用户以自然语言描述需求，系统自动生成工作流草图；
5. **实时执行监控**：通过 WebSocket 实现执行过程的实时推送；
6. **RAG 知识增强**：提供完整的检索增强生成管线；
7. **多租户与团队协作**：支持团队成员权限管理与工作流共享。

### 1.1.3　设计约束与可行性分析

- **技术栈选型**：前端 Vue 3 + Vite + Element Plus + Vue Flow，后端 Django 5 + DRF，均为业界主流框架，社区资源丰富；
- **开发时间**：课程时间为 2026.4.20—2026.4.30（约 10 天），优先实现核心功能；
- **成本约束**：优先使用开源技术栈，开发测试成本可控。

## 2.4　设计实现方案

### 2.4.1　系统架构设计

Flowly 平台采用**分层架构**设计，从上至下分为四个层次：

```
┌─────────────────────────────────────────────┐
│           Presentation Layer (前端)            │
│  Vue 3 + Vite + Element Plus + Vue Flow      │
├─────────────────────────────────────────────┤
│            Business Layer (后端)               │
│  Django REST Framework + Django Channels      │
│  LangChain / LangGraph / Celery               │
├─────────────────────────────────────────────┤
│              Data Layer                       │
│  MySQL 8.0 + Redis 7 + 向量数据库             │
├─────────────────────────────────────────────┤
│           Infrastructure Layer                 │
│  Docker + Nginx + Linux                       │
└─────────────────────────────────────────────┘
```

**前后端通信机制：**

- **HTTP REST API**：所有 CRUD 操作通过 RESTful API 完成，由 Axios 封装调用；
- **WebSocket**：工作流执行日志、Agent 对话流式输出通过 WebSocket 实时推送（基于 Django Channels + Redis）；
- **Celery + Redis**：耗时任务通过 Celery 异步处理，结果通过 WebSocket 回调推送。

### 2.4.2　数据模型设计

核心数据模型：

- **Tenant（租户）**：多租户隔离，每个租户拥有独立的用户、工作流和 Agent
- **User（用户）**：继承 Django 内置 User 模型，关联 Tenant，支持 JWT 认证
- **Workflow（工作流）**：核心实体，存储工作流元数据、DAG 定义（JSON）、状态和执行统计
- **WorkflowNode（工作流节点）**：节点定义，包含类型、位置、配置参数（JSON）、输入输出映射
- **WorkflowExecution（工作流执行记录）**：每次执行的记录，包含输入参数、执行状态、结果输出、错误信息

### 2.4.3　关键算法设计

**工作流 DAG 解析算法：**

工作流以有向无环图（DAG）形式存储，节点表示操作步骤，边表示数据流向。执行引擎通过拓扑排序确定节点执行顺序：

1. 从"开始节点"出发，递归遍历所有连接的节点，构建邻接表；
2. 计算每个节点的入度（in-degree）；
3. 使用 Kahn 算法进行拓扑排序，生成执行队列；
4. 按执行队列顺序调度节点，节点间通过异步 Future 等待依赖完成；
5. 支持条件节点和路由节点的分支逻辑，根据执行结果动态选择后续路径。

## 3.2　模块设计（成员一负责：前端可视化编辑器）

### 3.2.1　模块一：可视化工作流编辑器

可视化工作流编辑器是本项目最核心的前端模块，基于 **Vue Flow** 实现，提供类 Figma 的流畅编辑体验。

**核心功能：**

- 支持拖拽节点库中的节点到画布；
- 节点之间通过拖拽连线建立数据流向关系；
- 选中节点后弹出配置面板，设置节点参数；
- 支持多选、复制、粘贴、删除节点；
- 支持画布缩放（鼠标滚轮）、平移（鼠标中键拖拽）；
- 支持撤销（Ctrl+Z）和重做（Ctrl+Y），基于命令模式实现；
- 支持工作流草稿自动保存（每 30 秒）；
- 支持全屏编辑模式和节点搜索定位。

**技术实现：**

Vue Flow 是基于 Vue 3 的节点编辑器库，核心 API 包括：

```typescript
import { VueFlow, useVueFlow } from '@vue-flow/core'
import { Background } from '@vue-flow/background'
import { Controls } from '@vue-flow/controls'
import { MiniMap } from '@vue-flow/minimap'

// 画布初始化
const { onConnect, addEdges, onNodeDragStop } = useVueFlow()

// 监听节点连接事件
onConnect((params) => {
  addEdges([{
    id: `e${params.source}-${params.target}`,
    source: params.source,
    target: params.target,
    type: 'smoothstep'
  }])
})
```

**撤销/重做实现（命令模式）：**

```typescript
class CommandHistory {
  private history: Command[] = []
  private index: number = -1

  execute(command: Command) {
    command.do()
    this.history = this.history.slice(0, this.index + 1)
    this.history.push(command)
    this.index++
  }

  undo() {
    if (this.index >= 0) {
      this.history[this.index].undo()
      this.index--
    }
  }

  redo() {
    if (this.index < this.history.length - 1) {
      this.index++
      this.history[this.index].do()
    }
  }
}
```

**useWorkflowStore：**

```typescript
export const useWorkflowStore = defineStore('workflow', () => {
  const nodes = ref<VueFlowNode[]>([])
  const edges = ref<VueFlowEdge[]>([])
  const selectedNodeId = ref<string | null>(null)
  const isDirty = ref(false)
  const commandHistory = new CommandHistory()

  // 节点操作
  function addNode(node: VueFlowNode) {
    const cmd = new AddNodeCommand(nodes, node)
    commandHistory.execute(cmd)
    isDirty.value = true
  }

  function deleteNode(nodeId: string) {
    const node = nodes.value.find(n => n.id === nodeId)
    if (node) {
      const cmd = new DeleteNodeCommand(nodes, edges, node)
      commandHistory.execute(cmd)
      isDirty.value = true
    }
  }

  function undo() { commandHistory.undo() }
  function redo() { commandHistory.redo() }

  return { nodes, edges, selectedNodeId, isDirty, addNode, deleteNode, undo, redo }
})
```

**useAuthStore：**

```typescript
export const useAuthStore = defineStore('auth', () => {
  const token = ref(localStorage.getItem('token'))
  const userInfo = ref<UserInfo | null>(null)

  async function login(credentials: LoginDTO) {
    const res = await authApi.login(credentials)
    token.value = res.data.token
    userInfo.value = res.data.user
    localStorage.setItem('token', res.data.token)
  }

  function logout() {
    token.value = null
    userInfo.value = null
    localStorage.removeItem('token')
  }

  return { token, userInfo, login, logout }
})
```

# 第 4 章　总结与体会

## 4.1　项目总结

本次课程设计历时约十天，从需求分析、方案设计到编码实现，完整地经历了一个中等规模全栈项目的开发流程。本人负责的 **前端可视化编辑器模块**，基本完成了预定的核心功能需求。

### 4.1.1　主要成果

1. **可视化工作流编辑器**：基于 Vue Flow 实现了功能较完整的拖拽式工作流编辑器，支持 14 种节点类型，覆盖了常见的 AI 工作流场景；
2. **通用 UI 组件库**：封装了 AppButton、AppCard、AppModal 等统一风格组件库，保证了项目 UI 的一致性；
3. **前端状态管理**：通过 Pinia 实现了工作流编辑器状态、认证状态、Agent 状态的模块化管理；
4. **工作流执行页面**：实现了包含 WebSocket 实时日志、DAG 节点状态可视化、执行结果展示的执行页面；
5. **前端工程化**：搭建了完整的 Vue 3 + TypeScript + Vite 工程结构，配置了 ESLint、路由、Axios 等基础设施。

### 4.1.2　存在的不足

1. **编辑器性能优化不足**：在较大规模工作流（>200 节点）场景下，前端渲染性能有待优化，尚未引入虚拟化或懒加载策略；
2. **多人协作编辑未实现**：计划中的多人实时协作编辑功能（基于 CRDT 算法）因时间限制未能实现；
3. **节点类型有限**：部分高级节点类型（如并行分支、并行循环）的交互设计尚未完善。

## 4.2　技术收获

1. **Vue 3 Composition API 深入实践**：掌握了 setup 语法糖、ref/reactive、watchEffect、computed 等核心 API，理解了组合式函数（composables）的设计理念；
2. **Vue Flow 可视化编辑器开发**：深入理解了 Vue Flow 的节点/边数据模型、拖拽交互、缩放平移等底层实现，能够开发自定义节点组件；
3. **Pinia 状态管理模式**：掌握了 Pinia 的 options API 和 setup API 两种写法，理解了 store 间的跨模块调用和持久化策略；
4. **TypeScript 类型系统应用**：在项目中广泛应用了泛型、接口、类型推断，提升了前端代码的类型安全性和可维护性；
5. **WebSocket 前端集成**：通过 WebSocket 实现了工作流执行日志的实时接收和展示，理解了全双工通信协议在前端的应用。

## 4.3　改进方向

1. **性能优化**：引入节点虚拟化（只渲染可视区域节点）、增量渲染、Web Worker 等方式优化大图性能；
2. **协作编辑**：引入 Y.js 或 CRDT 算法实现多人实时协作编辑；
3. **节点市场**：构建节点模板市场，支持用户上传和分享自定义节点；
4. **快捷键系统**：完善全局快捷键系统，提升编辑效率；
