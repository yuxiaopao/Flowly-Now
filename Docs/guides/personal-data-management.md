# 个人工作区备份、恢复与清理

入口为设置页的「数据管理」。接口统一位于 `/api/v1/data-export/`，均要求登录，历史记录、下载、恢复计划和备份策略按当前用户隔离。

## 导出与备份范围

导出在创建时保存不可变快照，之后的下载不会重新读取最新业务数据。个人工作区备份包含：

- 当前个人工作流的节点、连线、变量、触发器、Webhook 配置。
- 个人 Agent 的配置和关联工具定义。
- 执行与审计记录的归档数据；恢复时不会重放这些执行。

团队工作区、已发布应用版本、知识库文件、模型权重、独立凭证库及账单不属于这个备份范围。工作流或工具配置中原本直接填写的敏感内容也属于其配置，因此 JSON 备份应按私人配置文件保管。

JSON 是可恢复格式，快照包含 `type=flowly_personal_backup` 和 `schema_version=1`。CSV、Excel 提供实际记录内容用于查看。Excel 字段超过单元格字符限制时，接口明确拒绝并提示改用 JSON 或 CSV，避免截断内容。

日期筛选对工作流和 Agent 使用创建时间，对执行记录使用排队时间，对使用记录使用计费周期开始时间。JSON 备份中的时间以带时区的 ISO 格式保存。

旧导出记录没有历史快照，无法恢复过去的数据；需重新创建 JSON 备份。旧记录下载会明确提示缺少快照，不会以当前数据冒充历史备份。

## 恢复为副本

1. 点击备份的「恢复为副本」，服务端校验版本、字段、节点引用和所属用户，返回预览。
2. 明确确认后，在一个事务中创建新资源并映射工作流、节点、边、变量、Agent 和工具 ID。
3. 工作流恢复为私有草稿；触发器、Webhook 保持禁用，Webhook 入口重新生成。原始内容保留。

确认令牌绑定当前用户、备份及其摘要，默认十分钟内有效。重复确认同一恢复操作返回第一次的结果，不重复创建。校验失败、数据变化或数据库写入失败时不会留下部分副本。

## 服务端自动备份

策略通过 `GET/PATCH /api/v1/data-export/backup_settings/` 持久保存，可选择每天、每周或每月执行，并设置保留数量。页面显示下一次运行时间、最近成功时间和最近失败信息。

`config.settings.CELERY_BEAT_SCHEDULE` 已登记 `core.tasks.run_due_personal_backups`。生产 Compose 的 `celery` 和 `celery-beat` 服务必须运行；仅启动 Web 服务不会执行计划。开发环境可在 `Backend` 目录分别运行项目的 Celery Worker 与 Beat 启动命令。

任务锁定策略行，避免重复投递创建同一时间段的备份。保留策略仅删除该用户的自动备份，手动导出不受影响。失败会记录错误并安排下一次重试，不会生成伪造的成功历史。

可在 Django 设置中覆盖以下上限，默认值集中在 `core/data_constants.py`：

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `PERSONAL_DATA_MAX_BYTES` | 20 MiB | 单份快照大小上限 |
| `PERSONAL_DATA_MAX_RECORDS` | 50,000 | 单次导出、恢复或清理的记录上限 |
| `PERSONAL_DATA_CONFIRMATION_SECONDS` | 600 秒 | 恢复、清理确认有效期 |

调度扫描间隔、备份保留范围及频率定义也集中在该常量模块。修改计划频率会从保存时刻重新安排下一次备份。

## 清理个人工作区

「清理个人工作区」先生成确切预览，再要求当前密码和文字 `删除个人工作流和Agent`。确认仅删除预览中的个人工作流、Agent 及其关联配置、执行和对话。

团队、已发布应用、账号、凭证、知识库、备份和账单保留。排队或运行中的任务、预览后的数据变化、可能级联到其他用户或团队的旧关联都会返回冲突，要求先处理关联或重新预览。没有通用 SQL、目录删除或账单清除入口。

部署前应用 `core` 的 `0002` 至 `0004` 数据库迁移。测试使用隔离数据库与样例文件，不运行真实业务数据清理。
